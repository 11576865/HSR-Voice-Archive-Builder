启动

Windows 与 Android / Termux 使用同一套项目逻辑，启动器不同。

Windows

DESKTOP HOST

适合长期构建、FFmpeg 处理和局域网控制。

Python 3.11+ FFmpeg in PATH Git 可选
NORMAL START · POWERSHELL / CMD 
cd HSR-Voice-Archive-Builder
.\run_windows.bat

首次获取：可以用 Git 克隆仓库，也可以从 GitHub 下载 ZIP 后解压。启动器接受 python，也会回退到 py -3；要求 Python 3.11 或更新版本。

脚本实际会做：检查 Python 版本 → 检查 Python 依赖 → 缺失时执行 pip install -r requirements.txt → 检查 FFmpeg 是否在 PATH → 启动本地控制台。正常情况下浏览器会自动打开；否则访问 http://127.0.0.1:8765/。

日常运行保留控制台窗口；关闭窗口即停止本地服务。
Git 更新Git 克隆方式可先执行 git pull --ff-only，再运行批处理。
端口占用可用 python -m app.launch --port 8766 改端口。
局域网控制：运行 run_windows_lan.bat。它绑定局域网地址并输出带随机 token 的 URL；处理仍发生在 Windows 主机。LAN 启动器要求 python 命令可用。

Android / Termux

MOBILE HOST

使用轻量 stdlib 服务端与 Termux 原生工具链。

Termux Git Python / FFmpeg / 7-Zip 自动检查
NORMAL START · TERMUX 
cd ~/HSR-Voice-Archive-Builder
git pull --ff-only
bash run_termux.sh

脚本实际会做：缺少时安装 Python、FFmpeg 和 7-Zip → 检查轻量依赖 → 缺失时执行 pip install -r requirements-termux.txt → 运行 app.launch --lite --no-browser。

控制台地址：脚本不会自动拉起 Android 浏览器；保持 Termux 运行，再在浏览器打开 http://127.0.0.1:8765/。

首次安装安装 Git、克隆仓库，然后运行 bash run_termux.sh。
服务端使用 dependency-light 的 stdlib HTTP server。
后台限制Android 可能终止长时间 CPU 密集任务；项目有恢复状态，但 FLAC 编码会重新开始。

处理范围

首页只列核心模块；具体状态与参数以本机控制台为准。

Archivecontinuous.flac、manifest、resolved Timeline 与构建报告。
SubtitleSRT、人工校对、ASS 排版与 FFmpeg / libass 实际渲染检查。
Incremental Update识别新增、变化与冲突条目；对不安全匹配保留人工确认。
Export可选 ASS、黑屏 MKV、训练集与参考语音包等派生产物。
Windows 首次准备下载仓库、Python、FFmpeg 与依赖 ⌄

安装 Python 3.11 或更新版本，并确认 python --version 或 py -3 --version 可用。安装 FFmpeg 后确认 ffmpeg -version 可用。Git 只在你希望用 git clone / git pull 更新时需要。

如果批处理窗口出现错误后停住，直接阅读窗口中的报错；run_windows.bat 失败时会保留窗口并等待按键。

Termux 首次安装只做一次 ⌄
TERMUX · FIRST INSTALL 
pkg install -y git
cd ~
git clone https://github.com/11576865/HSR-Voice-Archive-Builder.git
cd HSR-Voice-Archive-Builder
bash run_termux.sh
输出语义固定档案状态与按需成品 ⌄

固定核心输出包括 continuous.flac、SRT、manifest、resolved Timeline 与构建报告；ASS 和黑屏 MKV 属于按需生成的成品。内部恢复与 QA 状态位于项目 .state/，不等同于最终输出目录。
